# Рендер вертикального ролика

Команда работает локально, без новых запросов к OpenRouter или ElevenLabs.
Вход: прошедший сверку сценарий, соседний `.review.json`, комплект TTS
`audio.wav` + `timings.json`. Контрольные суммы связывают их между собой.
Изменённые тексты, аудио, неполные/пересекающиеся метки и карантинные сценарии
отклоняются до рендера. Результат остаётся на ручной приёмке.

## Запуск

В Docker уже установлены FFmpeg/ffprobe, libass и шрифт с кириллицей:

```bash
docker compose build
docker compose run --rm agent python -m app render \
  --input drafts/reel-script-ID.json \
  --timings audio/tts-ID/timings.json
```

Локально нужен Python 3.11+, зависимости проекта, FFmpeg с `libx264`, AAC,
фильтром `ass`/libass и установленным шрифтом `DejaVu Sans` либо своим
шрифтом с поддержкой кириллицы. Команда та же без `docker compose run --rm agent`.
Python читает `.env` из текущей папки проекта; Compose передаёт его как окружение.

Выбор оформления и локального фона:

```bash
python -m app render --input drafts/reel-script-ID.json \
  --timings audio/tts-ID/timings.json \
  --template templates/default.yaml --clips-dir backgrounds --output-dir renders
```

`--clips-dir` необязателен: без него используется вертикальный градиент.
Поддерживаются 1–20 файлов `.mp4`, `.mov`, `.mkv`, `.webm` непосредственно
в папке. Они идут по имени, приводятся к одному размеру и частоте кадров,
обрезаются по центру для заполнения 9:16 и повторяются, если короткие.
Длинный клип используется максимум на длительность ролика. Собственный звук
клипов убирается. Дополнительные загрузки материалов не выполняются.
В Compose папка `backgrounds/` подключена только для чтения.

## Настраиваемый финальный экран

В `templates/default.yaml` укажите свои значения:

```yaml
service_name: 'Название вашей услуги'
contact: 'Ваш сайт или контакт'
end_seconds: 3
```

Это пример полей, а не данные, добавленные в шаблон. По умолчанию оба поля
пустые: показываются согласованный CTA из `SCRIPT_CTA` и обязательный
дисклеймер. Название ограничено 80 символами, контакт — 120, без переносов.
Собственные YAML-шаблоны можно хранить рядом и выбирать через `--template`
или `RENDER_TEMPLATE`. Цвета, шрифт, верхний заголовок `header_text`, размер титров, число слов на экране и
длительность финального экрана также настраиваются. Неизвестные поля и
выход за допустимые диапазоны вызывают понятную ошибку.

## Оформление и ограничения

- Выход — MP4, H.264, `yuv420p`, AAC 48 кГц, 1080×1920, 30 кадров/с,
  `faststart`. Параметры и длительности потоков проверяет ffprobe.
- Крупные субтитры строятся из **всей озвучки** по таймингам слов, включая
  хук и CTA. Группы до 5 слов (настраивается), до 42 символов, две строки
  примерно по 21 символу; слишком длинное отдельное слово отклоняется.
  Это синхронные субтитры, отдельные поля `on_screen_text` не дублируются.
- Плашка содержит закон, статью, часть при наличии и полный URL из проверенного
  сценария. Если норм несколько, карточки сменяются равными интервалами
  в течение озвучки. Очень длинная карточка отклоняется, а не обрезается.
- Дисклеймер «Не является юридической консультацией» виден весь ролик.
  Фоновые клипы затемняются для читаемости; правовой текст не дописывается.
- Не более **90 секунд вместе с финальным экраном**. Длинную озвучку нужно
  перегенерировать: речь не ускоряется и не обрезается. Конец округляется
  вниз к сетке 30 кадров/с, максимум на 1/30 с в добавленной финальной паузе.
  Целевой редакционный диапазон 30–60 секунд остаётся рекомендацией.
- При `timing_source: estimated` видео сохраняет эту пометку. Реальную
  точность синхронизации нужно оценивать по речи; оценка не становится
  таймингами провайдера после рендера.

Каждый запуск создаёт новую папку `renders/render-<uuid>/`:

- `video.mp4` — готовый ролик;
- `subtitles.ass` — сохранённые текст и расписание титров/плашек;
- `render.json` — настройки, контрольные суммы, данные ffprobe и статус
  `human_review_required: true`, `publication_allowed: false`.

Файлы появляются вместе только после успешной проверки. При ошибке временные
результаты удаляются, прежние ролики не заменяются. Рендер не публикует видео
и не отмечает тему использованной. Обработка FFmpeg ограничена десятью минутами
на операцию, ffprobe — тридцатью секундами. Коды CLI: 0 — готово, 2 — ошибка.

Переменные окружения: `RENDER_OUTPUT_DIR`, `RENDER_TEMPLATE`, `FFMPEG_BIN`,
`FFPROBE_BIN`. Ключи внешних сервисов для рендера не нужны.

## Проверки

```bash
python -m pytest -q
docker compose run --rm agent sh -c 'python -m pip install -r requirements-dev.txt && python -m pytest -q && python -m pip check'
```

Два интеграционных теста действительно рендерят 27-секундные видео
1080×1920 и проверяют их через ffprobe. Если локальных FFmpeg/ffprobe нет,
только эти тесты пропускаются; в Docker выполняются оба. Аудио в тестах —
синтетическая тишина, нормы и источники — явно учебные фикстуры.
Сетевые вызовы запрещены общей фикстурой тестов.

После добавления своих данных проверьте финальный экран, читаемость полного
URL на телефоне и синхронизацию с настоящей озвучкой ElevenLabs. Перед
использованием ролика редактор проверяет юридический смысл и актуальность
по первоисточнику.

Справочник реализации: [фильтры FFmpeg](https://www.ffmpeg.org/ffmpeg-filters.html),
[JSON-вывод ffprobe](https://www.ffmpeg.org/ffprobe.html).

Результаты выполненных проверок: [render_verification.md](render_verification.md).
