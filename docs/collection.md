# Сбор и отбор юридических тем

Текущий этап добавляет `collect` и `mark-used`. Генерация сценария и видео
не запускается. Настройки — в корневом `sources.yaml`.

## Быстрый запуск

```bash
python -m pip install -r requirements-dev.txt
# Задайте OPENROUTER_API_KEY через окружение. Не сохраняйте ключ в Git.
python -m app collect
python -m app collect --count 2 --max-age-days 30
```

По умолчанию: **одна тема на ролик, свежесть 30 дней**. Обе величины меняются
в YAML (`topics_per_video`, `freshness_days`) и аргументами команды. Код
возврата: 0 — нужное количество отобрано; 3 — подходящих тем меньше;
2 — ошибка конфигурации, сети/модели или отсутствие собранных материалов.
Недостающие темы не придумываются.

`collect` использует OpenRouter для смыслового сравнения. Без ключа команда
завершается с понятной ошибкой. Локального незаметного обхода смысловой проверки
нет. Python не читает `.env` автоматически; Docker Compose передаёт его
через `env_file`.

```bash
docker compose build
docker compose run --rm agent python -m app collect
```

Команда печатает идентификаторы отобранных тем и путь к JSON, по умолчанию
`data/collected_topics.json`. SQLite хранится в `data/topic_history.sqlite3`.
В Compose каталог `./data` подключён к `/app/data`, поэтому история сохраняется
после удаления контейнера. Оба пути можно переопределить через `--history` и
`--output`, путь к списку источников — через `--sources`.

## Источники

| Источник | Формат | Адрес |
| --- | --- | --- |
| Официальное опубликование | HTML | https://publication.pravo.gov.ru/documents |
| Государственная Дума | HTML | https://duma.gov.ru/news/ |
| Конституционный Суд | HTML | https://www.ksrf.ru/news/ |
| Верховный Суд | HTML | https://vsrf.ru/news |
| ФНС России | RSS | https://www.nalog.gov.ru/rn77/rss/ |
| Роструд | HTML | https://rostrud.gov.ru/press_center/novosti/ |
| Право.ru | RSS | https://pravo.ru/rss/ |
| РАПСИ | HTML | https://rapsinews.ru/news/ |

У источника задаются `id`, `name`, `url`, `format: rss|html`,
`kind: official|media`. Для HTML обязательный `item_selector` выбирает карточки
или ссылки списка; остальные CSS-селекторы задают заголовок, ссылку, дату,
описание и текст полной страницы. `link_pattern` ограничивает ссылки на статьи.
`enabled: false` отключает источник. TLS-проверка не отключается.
Для RSS ФНС и Право.ru включены `article_https` и `article_trailing_slash`:
живые ссылки без `/` возвращали 404 или зацикливали перенаправление.
Эти правила применяются только к тому же хосту, что и источник.

На момент проверки часть официальных сайтов не отвечала из этой среды:
pravo.gov.ru и duma.gov.ru — таймауты; ksrf.ru и vsrf.ru — ошибки TLS;
Роструд — отказ/страница без подходящих карточек. Они оставлены в конфиге
с явными диагностическими ошибками при запуске. Селекторы этих недоступных
страниц требуют проверки при восстановлении доступа. Ошибки отдельных сайтов
не останавливают доступные источники и отражаются в `source_errors`.

Рабочие RSS-пути ФНС и Право.ru подтверждены ссылками на самих сайтах.
Новости РАПСИ доступны; даты извлекаются из полной страницы. Полный результат
проверки доступности сохраняется отдельно в отчёте этого этапа.

## Правила обработки

1. Загрузить RSS/Atom или HTML-список и страницы материалов. Таймаут, число
   попыток и максимальный размер ответа ограничены. Переход на другой
   неразрешённый домен блокируется, в том числе при перенаправлении.
2. Извлечь заголовок, текст, ссылки и дату. Относительные даты вроде «вчера»
   не додумываются. Дата без часового пояса интерпретируется как МСК (UTC+3).
   Без даты или при дате в будущем тема не проходит фильтр свежести.
3. Локально объединить одинаковые URL и полностью совпадающие содержательные
   тексты с заголовками. Удаляются параметры аналитики, но сохраняются
   значимые `id`, `date`, `from` и другие параметры. Ссылки всех публикаций
   остаются в объединённой теме.
4. Из свежих тем взять не больше `max_candidates`, начиная с новых. Число
   отброшенных по лимиту указано в `candidates_truncated`.
5. Через OpenRouter сравнить оставшиеся темы между собой и **со всей** историей
   использованных. Сравнения разбиваются на ограниченные группы; проверяются
   и пары из разных групп. Одинаковый номер закона или дела сам по себе не
   считается дублем. Новая стадия дела или другое изменение остаются отдельно.
6. Модель возвращает только группы переданных идентификаторов. Программа
   проверяет полноту и уникальность: придуманные/пропущенные id приводят к
   ошибке без сохранения новой подборки. Инструкции внутри статей считаются
   недоверенными данными. Исходные тексты и ссылки не переписываются моделью.
7. Найти реквизиты непосредственно в исходном тексте и прямую ссылку на документ
   из `primary_hosts`. Главная страница, новость ведомства или ссылка на СМИ
   сами по себе не являются первоисточником. Документ должен быть доступен;
   HTML дополнительно должен содержать совпадающий реквизит. Для PDF
   проверяется доступность прямого файла, без проверки его юридического смысла.
8. Отобрать по практической пользе для предпринимателей и потенциальных
   клиентов юридических услуг, свежести публикации и наличию первоисточника.
   Польза оценивается открытыми словарями проблем в `topic_selection.py`:
   договоры, налоги, взыскание, споры, увольнение, наследство и т. д.
   Вес пользы — до 60 баллов, свежести — до 25, первоисточника — 15.
   Причины и аудитория включаются в JSON.

Смысловая проверка зависит от модели и фрагментов текста: она может ошибаться.
Расход API растёт с числом кандидатов и использованных тем. Стоимость здесь
не фиксируется. Свежесть означает дату публикации материала, а не дату
вступления нормы в силу. Извлечение реквизитов и доступность документа
не гарантируют правильность толкования, действующую редакцию или соответствие
PDF цитате: это остаётся редакционной проверкой.

## Подтверждение использования

После фактического использования темы выполните:

```bash
python -m app mark-used topic-ИДЕНТИФИКАТОР
# Можно подтвердить несколько тем одновременно:
python -m app mark-used topic-ПЕРВЫЙ topic-ВТОРОЙ --history data/topic_history.sqlite3
```

До этой команды повторный `collect` может снова предложить тему. После
подтверждения исключаются её URL и смысловые перефразировки. Команда принимает
только сохранённые идентификаторы; неизвестный id отменяет всю операцию.
Повторное подтверждение безопасно и не меняет первую дату использования.
История содержит снимки использованных тем и всех их источников.

Каждая отобранная тема имеет статус `review_required`; это не публикация
и не подтверждение её юридической достоверности.
