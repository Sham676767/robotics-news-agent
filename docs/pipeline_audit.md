# Итоговый аудит пайплайна

Дата: 24 октября 2026 года. База — этап Instagram/S3; реальные ключи и
публикация в аккаунт для этого аудита не использовались.

## Dry-run на тестовых данных

Конфигурация: `tests/fixtures/preflight.env` и `tests/fixtures/preflight.yaml`,
стандартный шаблон оформления. Ключи синтетические, URL используют примерные
домены; версия Meta в фикстуре проверяет формат и не рекомендует рабочую версию.
Перед запуском создана тестовая SQLite-история с одной использованной темой.

CLI запущена отдельным процессом в Docker/Python 3.11 с настоящими
FFmpeg/ffprobe, libass и DejaVu Sans. Сеть отключена через `--network none`,
корень контейнера и проект подключены read-only. Входы скопированы во временную
папку `/tmp` до снимка файлов. Сравниваются состав папки, SHA-256 файлов и
время изменения до/после каждой команды.

| Вариант | Результат | Код выхода | Файлы и история |
| --- | --- | --- | --- |
| `run-all --dry-run --count 2`, тестовые ключи | `ready: true`, live-план | 0 | Без изменений |
| `run-all --dry-run --stub` | `ready: true`, платных запросов 0 | 0 | Без изменений |
| `run-all --dry-run`, ключи отсутствуют | `ready: false`, список проблем | 2 | Без изменений |

Live-план показывает модель `fixture/model`, голос `fixture-voice`, 2 ролика,
генерацию и сверку для каждого, TTS и верхнюю оценку смысловых сравнений с
историей. S3/Instagram перечислены как действия только после отдельного
одобрения. Ни OpenRouter, ни ElevenLabs, ни S3, ни Graph API не вызывались.
JSON запуска сохранён как отдельный артефакт `pipeline-audit/dry-run.json`.

Dry-run по согласованному контракту **не исполняет этапы пайплайна**. Полный
проход с реальным FFmpeg-рендером проверяется интеграционным тестом `--stub`.
Live-последовательность от коллектора до полного черновика, отказы сверки,
TTS/рендера и публикационные операции проверяются с моками внешних API.

## Тесты и покрытие

Docker/Python 3.11: **580 тестов пройдено, пропусков нет**. В том числе:

- реальный рендер градиента, фоновых клипов и полного stub-комплекта;
- реальный CLI dry-run с загрузкой синтетического `.env` и запретом сети;
- отсутствие записи в историю, создания API-клиентов и операций S3 в dry-run;
- некорректный YAML, все отключённые источники, неверное число роликов;
- отсутствие шаблона, libass или шрифта, ошибки/таймауты локальных инструментов;
- недоступные папки, некорректная история, короткий TTL и неподдерживаемый TTS;
- ранее добавленные правила сценария, сверка источников, одобрение,
  неизменность файлов, ретраи, квоты и восстановление после потери ответа.

Покрытие coverage.py, **все модули `app`**, без исключения непокрытых модулей:

| Показатель | Результат |
| --- | --- |
| Исполняемые строки | 2773 / 2917 — **95,06%** |
| Ветви условий | 835 / 956 — **87,34%** |
| Совокупный показатель coverage.py | **93,16%** |
| Минимум в `.coveragerc` | 90% совокупно |

Остаются 144 строки и 121 ветвь без покрытия, преимущественно дополнительные
варианты ошибок и проверок конфигурации/материалов. Это не заявление о 100%
проверке всех исключительных ситуаций. Например, `publishing_config` имеет
78,15% совокупного покрытия, `reel_drafts` — 84,71%; полный HTML показывает
точные строки. Проверка чтения/формата ключей не доказывает их действительность.

После удаления неиспользуемых импортов в тестах дополнительно пройдены
102 затронутых теста. `pip check`, Pyflakes для `app`, `main.py`, `scripts`,
`tests` и Vulture для прикладного кода с уверенностью от 90% — без замечаний.
Vulture с порогом 60% также просмотрен вручную: его оставшиеся срабатывания
относятся к совместимой настройке `APP_ENV`, полям dataclass/LogRecord,
используемым через сериализацию и стандартное логирование.

## Уборка и воспроизведение

Удалены 4 неиспользуемых импорта: один в `topic_dedup`, три в тестах.
Подтверждённых мёртвых функций или модулей при анализе не обнаружено.
Существующая команда локальных текстовых черновиков сохранена как работающий
интерфейс, а не объявлена мёртвым кодом. Источники без единого включённого
элемента теперь отклоняются до начала сбора.

```bash
python -m pip install -r requirements-dev.txt
python -m coverage run -m pytest -q
python -m coverage report
python -m coverage html
python -m pyflakes app main.py scripts tests
python -m vulture app main.py scripts --min-confidence 90
python -m pip check
```

Для полного прогона нужен Docker-образ с медиазависимостями; инструкция есть
в README. На компьютере без FFmpeg соответствующие тесты будут пропущены.
HTML (`htmlcov/index.html`), данные coverage и JSON dry-run передаются отдельно
от исходников. Секреты и результаты генерации в репозиторий не добавлялись.
