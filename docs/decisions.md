# Решения текущего этапа

## 2026-10-22 — очистка основы

1. Рабочее имя приложения — **Legal Reels Agent**, `legal-reels-agent`.
   Репозиторий GitHub не переименовываем: изменение его адреса не требуется
   для очистки кода.
2. Не заменяем словарь робототехники придуманным списком правовых норм,
   новостных источников или юридических приоритетов. Источники и генерация
   сценариев требуют отдельного этапа. Автоматическая генерация сейчас
   не запускается, клиент OpenRouter остаётся библиотечным модулем.
3. Минимальный контракт черновика сохраняет устройство исходной статьи:
   заголовок, вступление, блоки текста и привязку к источникам. Имена меняются
   на `LegalDraft`, `LegalSection`, `LegalSource`, `source_index`. Нет квоты
   в пять блоков и правил ежедневного выпуска. Это промежуточный текстовый
   черновик, не контракт сценария, не готовое видео.
4. Черновик принимается локально в JSON вместе с исходными материалами.
   У материала обязательны название, издатель/источник, URL и содержательный
   текст. Юрисдикция — `RU`. Поле `review_required` не снимается программой.
   Числовая и языковая проверки не подтверждают юридическую достоверность,
   актуальность редакции или полноту условий применения нормы.
5. Не переносим ретраи публикации как неиспользуемый модуль: сохраняем механизм
   ограниченных сетевых повторов в клиенте OpenRouter. Новые интеграции смогут
   использовать тот же подход, когда будут выбраны.
6. Старые выпуски, данные и инфраструктура удаляются из текущего дерева;
   архивом остаётся история Git. Существующие GitHub Secrets и настройки
   внешних сервисов этот этап не изменяет.
7. Сохраняем паузу GitHub Actions: тестовый workflow остаётся с суффиксом
   `.disabled`. Автопубликацию и расписание не включаем.
8. `.env.example` — образец для переменных окружения; приложение не читает
   `.env` автоматически. Docker Compose передаёт его через `env_file`.
   Локально переменные задаются средствами оболочки; пустой ключ разрешён,
   пока клиент OpenRouter не вызван явно.


## 2026-10-22 — сбор тем (согласовано с пользователем)

1. Аудитория — предприниматели и люди, которым может понадобиться юридическая
   услуга; это заменяет исходный критерий «обычный человек».
2. Стартовый список ведомств и СМИ подбирается самостоятельно. Включены
   четыре указанных официальных сайта, ФНС, Роструд, Право.ru и РАПСИ.
3. Локальные точные повторы объединяются до обращения к OpenRouter;
   модель сравнивает смысл оставшихся тем и историю. Источники сохраняются.
4. Тема считается использованной только после отдельной команды `mark-used`.
5. Окно свежести по последней поправке пользователя — **30 дней**, вместо
   первоначально выбранных 7. Число тем на ролик по умолчанию 1, настраивается.
6. Для технических лимитов заданы открытые значения в YAML: 15 материалов
   на источник, до 60 кандидатов, группы смыслового сравнения по 12.
   Отброшенные по лимиту кандидаты отражаются в отчёте.
7. Ошибки источников не скрываются и не обходятся отключением TLS. Для
   недоступных официальных страниц селекторы отмечены как требующие живой проверки.
8. Модель не генерирует правовые реквизиты или тексты тем: они берутся из
   публикаций. Неполный отбор не дополняется выдуманными темами.
9. Для типового HTML/RSS сохраняются ссылки и текст; доступность первичного
   PDF не равна проверке его содержания. Генерация и правовая редактура — следующие этапы.

## 2026-10-22 — сценарий

1. Согласовано с пользователем: `voiceover` содержит всю озвучку с хуком и CTA;
   ограничение 80–140 слов применяется к нему целиком. CTA по умолчанию —
   «Сохраните ролик и поделитесь им». Карточки `sources[]` содержат название,
   URL и реквизиты, в коде это `title`, `url`, `citation`.
2. Техническое представление структуры — четыре абзаца `voiceover`, разделённые
   пустыми строками: хук, суть, действия, CTA. Хук до восьми слов — приближение
   трёх секунд; фактическая длительность относится к этапу озвучки. Слово через
   дефис считается одним. CTA настраивается через `SCRIPT_CTA`.
3. Один `script` использует одну тему из сохранённого результата `collect`.
   При нескольких темах требуется `--topic-id`, чтобы не выбирать произвольно.
   Нестандартный путь подборки передаётся через `--input`; источник по умолчанию —
   `data/collected_topics.json`.
4. Названия первоисточников не придумываются: пока сборщик хранит реквизиты,
   они используются и в `title`. У новостной карточки `citation` пустой,
   первоисточники приведены отдельными карточками. Все карточки обязательны
   и сверяются с исходной подборкой целиком.
5. JSON-схема и предметные проверки выполняются локально независимо от поддержки
   схемы у провайдера. Ошибки JSON/схемы/содержания используют единый ограниченный
   цикл повторов OpenRouter, без вложенного умножения числа запросов.
6. Сценарий сохраняется отдельно в JSON строго с семью полями без метаданных;
   это всегда черновик для правовой редактуры. Успешная генерация не отмечает
   тему использованной. Числа и распознаваемые реквизиты проверяются ограниченно;
   смысловая истинность и актуальность права автоматически не подтверждаются.
7. Disclaimer фиксирован: «Информация носит общий характер и не заменяет
   индивидуальную юридическую консультацию.» Он не включается в озвучку
   автоматически. Текст можно вывести отдельной карточкой на будущем этапе видео.
8. Дополнительные зависимости для простого фиксированного контракта не нужны:
   JSON-схема передаётся модели, локально все семь полей и вложенные карточки
   проверяются явно, типизированный результат представлен dataclass.

## 2026-10-22 — проверка сценария по источникам

1. Согласованы лимиты: озвучка 80–140 слов, до 6 титров по 60 символов,
   подпись до 1000 символов, 1–10 хэштегов. Символы считаются как Unicode-кодовые
   точки, включая пробелы и пунктуацию. Титр — одна строка без переносов.
2. Согласовано расширение карточек `sources` полями `law`, `article`, `part`.
   У правового первоисточника нужна конкретная норма; часть может быть пустой
   для статьи без частей, что дополнительно проверяет LLM. У новостной карточки
   эти реквизиты пустые. Номера извлекаются из явных связок текста документа,
   не генерируются моделью и не достраиваются по отдельным числам.
3. Новый обязательный дисклеймер — **«Не является юридической консультацией»**.
   Это заменяет прежнюю формулировку из этапа сценариев.
4. К снимку первоисточника добавлен `content`, содержащий текст официального HTML.
   Старые снимки читаются, но без текста требуют нового сбора. PDF не объявляется
   прочитанным: до отдельного извлечения текста он не проходит сверку.
5. Вторая беседа с моделью из того же конфига сверяет заранее перечисленные
   фрагменты, включая CTA, хэштеги и реквизиты. Подтверждение требует URL
   и существующей цитаты от 12 до 600 символов. Пробелы нормализуются;
   совпадение цитаты не доказывает логическую правильность вывода.
6. Лимит повторов применяется отдельно к генерации и сверке (по умолчанию
   до 3 + 3 HTTP-запросов). Отрицательный валидный вердикт не повторяется ради
   одобрения. Сбой, невалидный ответ или недостаток доказательств блокируют результат.
7. При блокировке создаётся пакет в `drafts/quarantine/` с причинами и источниками;
   обычный `--output` не создаётся, stdout пуст, код выхода 3. При успехе stdout —
   JSON из семи полей, рядом пишется `.review.json`. `publication_allowed` всегда
   false: правовая приёмка и публикация в этот этап не входят.
8. Сверка привязана контрольными суммами к сценарию и снимку темы. Сохранение
   без успешной сверки или с изменёнными данными запрещено и в библиотечном
   интерфейсе. Генерация и сверка не отмечают тему использованной.
9. Словарь категоричных фраз и распознавание реквизитов не покрывают все формы.
   Оговорка учитывается в том же предложении; её содержательную достаточность
   и соответствие источнику проверяет LLM, затем редактор. Отдельный дисклеймер
   не оправдывает обещание результата.

## 2026-10-23 — озвучка и тайминги

1. Пользователь выбрал ElevenLabs и тайминги сервиса. Реализован общий
   `TTSProvider` с методом `synthesize(text)`, без файлового ввода-вывода.
   Реализация возвращает WAV, метаданные и необязательные тайминги слов.
   Сохранение и резервная оценка находятся в отдельном пайплайне. Для будущего
   OpenAI достаточно отдельного адаптера и регистрации в фабрике, ядро не меняется.
2. Ключ и `voice_id` задаются как `ELEVENLABS_API_KEY`, `ELEVENLABS_VOICE_ID`
   в `.env` для Docker Compose. Существующее правило сохранено: локальный Python
   сам `.env` не читает, использует переменные окружения. Ключи не выводятся
   в repr, логи и сохранённые метаданные. Пустые значения не мешают другим командам,
   но явно отклоняются при создании TTS-провайдера.
3. Выбран endpoint ElevenLabs `with-timestamps`, модель по умолчанию —
   `eleven_multilingual_v2`, настраиваемая через `ELEVENLABS_MODEL_ID`.
   Запрашивается PCM 24 кГц, mono, signed 16-bit LE; WAV собирается стандартной
   библиотекой. MP3-декодер, FFmpeg и новые зависимости не требуются.
4. Посимвольные метки группируются по непустым словам с сохранением пунктуации.
   Приоритет у `alignment`, затем у `normalized_alignment`, если слова совпадают
   с исходным текстом с учётом Unicode NFC и различий пробелов. Например, замена
   чисел словами в нормализованной версии не считается точной привязкой к исходнику.
   Проверяются полнота, конечность, порядок и границы. Допускается обрезать только
   до 20 мс округления за фактическим концом WAV; метки дальше отклоняются.
5. Если таймингов нет или корректные массивы относятся к другому тексту,
   используется `phrase_length_v1`: фактическая длительность WAV делится по
   длинам фраз и слов. Вес слова — число букв и цифр (минимум 1); вес паузы после
   `. ! ? …` — 6, после `, ; :` — 3, перед новым абзацем — минимум 9.
   Все веса масштабируются на длительность аудио. Финальная пунктуация может
   оставить оценочную паузу в конце. Это **допущение, а не распознавание речи**:
   метаданные явно содержат `timing_source: estimated`, метод и причину.
   Темп, ударения и реальные паузы этим способом точно не определяются.
6. Повреждённые массивы, отрицательные/NaN-метки, несовпадающие длины массивов,
   пересечения слов и повреждённое аудио вызывают ошибку, без тихой замены
   приблизительными метками. Успешный HTTP 200 с некорректным ответом повторно
   не генерируется, чтобы не создавать дополнительные оплачиваемые дубли.
   Только временные HTTP/транспортные ошибки повторяются ограниченно через `TTS_*`.
7. Команда `tts` принимает сценарий с успешной сверкой и проверяет её контрольные
   суммы, доказательства и текущие локальные правила до вызова провайдера.
   Озвучивается ровно `voiceover`, включая хук и CTA, без их повторного добавления.
   Дисклеймер остаётся отдельным полем для будущего оформления видео.
8. На выходе новая папка с `audio.wav` и `timings.json`, появляющимися вместе
   после успешной записи. Аудио и исходный текст привязаны контрольными суммами.
   История использования и разрешение публикации не меняются. Длительность
   сообщается фактическая: речь не обрезается и не ускоряется ради 30–60 секунд.
