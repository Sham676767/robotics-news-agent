# Решения текущего этапа

## 2026-10-22 — очистка основы

1. Рабочее имя приложения — **Legal Reels Agent**, `legal-reels-agent`.
   Репозиторий GitHub не переименовываем: изменение его адреса не требуется
   для очистки кода.
2. Не заменяем словарь робототехники придуманным списком правовых норм,
   новостных источников или юридических приоритетов. Источники и генерация
   сценариев требуют отдельного этапа. Автоматическая генерация сейчас
   не запускается, клиент OpenRouter остаётся библиотечным модулем.
3. Минимальный контракт черновика сохраняет устройство исходной статьи:
   заголовок, вступление, блоки текста и привязку к источникам. Имена меняются
   на `LegalDraft`, `LegalSection`, `LegalSource`, `source_index`. Нет квоты
   в пять блоков и правил ежедневного выпуска. Это промежуточный текстовый
   черновик, не контракт сценария, не готовое видео.
4. Черновик принимается локально в JSON вместе с исходными материалами.
   У материала обязательны название, издатель/источник, URL и содержательный
   текст. Юрисдикция — `RU`. Поле `review_required` не снимается программой.
   Числовая и языковая проверки не подтверждают юридическую достоверность,
   актуальность редакции или полноту условий применения нормы.
5. Не переносим ретраи публикации как неиспользуемый модуль: сохраняем механизм
   ограниченных сетевых повторов в клиенте OpenRouter. Новые интеграции смогут
   использовать тот же подход, когда будут выбраны.
6. Старые выпуски, данные и инфраструктура удаляются из текущего дерева;
   архивом остаётся история Git. Существующие GitHub Secrets и настройки
   внешних сервисов этот этап не изменяет.
7. Сохраняем паузу GitHub Actions: тестовый workflow остаётся с суффиксом
   `.disabled`. Автопубликацию и расписание не включаем.
8. `.env.example` — образец для переменных окружения; приложение не читает
   `.env` автоматически. Docker Compose передаёт его через `env_file`.
   Локально переменные задаются средствами оболочки; пустой ключ разрешён,
   пока клиент OpenRouter не вызван явно.


## 2026-10-22 — сбор тем (согласовано с пользователем)

1. Аудитория — предприниматели и люди, которым может понадобиться юридическая
   услуга; это заменяет исходный критерий «обычный человек».
2. Стартовый список ведомств и СМИ подбирается самостоятельно. Включены
   четыре указанных официальных сайта, ФНС, Роструд, Право.ru и РАПСИ.
3. Локальные точные повторы объединяются до обращения к OpenRouter;
   модель сравнивает смысл оставшихся тем и историю. Источники сохраняются.
4. Тема считается использованной только после отдельной команды `mark-used`.
5. Окно свежести по последней поправке пользователя — **30 дней**, вместо
   первоначально выбранных 7. Число тем на ролик по умолчанию 1, настраивается.
6. Для технических лимитов заданы открытые значения в YAML: 15 материалов
   на источник, до 60 кандидатов, группы смыслового сравнения по 12.
   Отброшенные по лимиту кандидаты отражаются в отчёте.
7. Ошибки источников не скрываются и не обходятся отключением TLS. Для
   недоступных официальных страниц селекторы отмечены как требующие живой проверки.
8. Модель не генерирует правовые реквизиты или тексты тем: они берутся из
   публикаций. Неполный отбор не дополняется выдуманными темами.
9. Для типового HTML/RSS сохраняются ссылки и текст; доступность первичного
   PDF не равна проверке его содержания. Генерация и правовая редактура — следующие этапы.

## 2026-10-22 — сценарий

1. Согласовано с пользователем: `voiceover` содержит всю озвучку с хуком и CTA;
   ограничение 80–140 слов применяется к нему целиком. CTA по умолчанию —
   «Сохраните ролик и поделитесь им». Карточки `sources[]` содержат название,
   URL и реквизиты, в коде это `title`, `url`, `citation`.
2. Техническое представление структуры — четыре абзаца `voiceover`, разделённые
   пустыми строками: хук, суть, действия, CTA. Хук до восьми слов — приближение
   трёх секунд; фактическая длительность относится к этапу озвучки. Слово через
   дефис считается одним. CTA настраивается через `SCRIPT_CTA`.
3. Один `script` использует одну тему из сохранённого результата `collect`.
   При нескольких темах требуется `--topic-id`, чтобы не выбирать произвольно.
   Нестандартный путь подборки передаётся через `--input`; источник по умолчанию —
   `data/collected_topics.json`.
4. Названия первоисточников не придумываются: пока сборщик хранит реквизиты,
   они используются и в `title`. У новостной карточки `citation` пустой,
   первоисточники приведены отдельными карточками. Все карточки обязательны
   и сверяются с исходной подборкой целиком.
5. JSON-схема и предметные проверки выполняются локально независимо от поддержки
   схемы у провайдера. Ошибки JSON/схемы/содержания используют единый ограниченный
   цикл повторов OpenRouter, без вложенного умножения числа запросов.
6. Сценарий сохраняется отдельно в JSON строго с семью полями без метаданных;
   это всегда черновик для правовой редактуры. Успешная генерация не отмечает
   тему использованной. Числа и распознаваемые реквизиты проверяются ограниченно;
   смысловая истинность и актуальность права автоматически не подтверждаются.
7. Disclaimer фиксирован: «Информация носит общий характер и не заменяет
   индивидуальную юридическую консультацию.» Он не включается в озвучку
   автоматически. Текст можно вывести отдельной карточкой на будущем этапе видео.
8. Дополнительные зависимости для простого фиксированного контракта не нужны:
   JSON-схема передаётся модели, локально все семь полей и вложенные карточки
   проверяются явно, типизированный результат представлен dataclass.

## 2026-10-22 — проверка сценария по источникам

1. Согласованы лимиты: озвучка 80–140 слов, до 6 титров по 60 символов,
   подпись до 1000 символов, 1–10 хэштегов. Символы считаются как Unicode-кодовые
   точки, включая пробелы и пунктуацию. Титр — одна строка без переносов.
2. Согласовано расширение карточек `sources` полями `law`, `article`, `part`.
   У правового первоисточника нужна конкретная норма; часть может быть пустой
   для статьи без частей, что дополнительно проверяет LLM. У новостной карточки
   эти реквизиты пустые. Номера извлекаются из явных связок текста документа,
   не генерируются моделью и не достраиваются по отдельным числам.
3. Новый обязательный дисклеймер — **«Не является юридической консультацией»**.
   Это заменяет прежнюю формулировку из этапа сценариев.
4. К снимку первоисточника добавлен `content`, содержащий текст официального HTML.
   Старые снимки читаются, но без текста требуют нового сбора. PDF не объявляется
   прочитанным: до отдельного извлечения текста он не проходит сверку.
5. Вторая беседа с моделью из того же конфига сверяет заранее перечисленные
   фрагменты, включая CTA, хэштеги и реквизиты. Подтверждение требует URL
   и существующей цитаты от 12 до 600 символов. Пробелы нормализуются;
   совпадение цитаты не доказывает логическую правильность вывода.
6. Лимит повторов применяется отдельно к генерации и сверке (по умолчанию
   до 3 + 3 HTTP-запросов). Отрицательный валидный вердикт не повторяется ради
   одобрения. Сбой, невалидный ответ или недостаток доказательств блокируют результат.
7. При блокировке создаётся пакет в `drafts/quarantine/` с причинами и источниками;
   обычный `--output` не создаётся, stdout пуст, код выхода 3. При успехе stdout —
   JSON из семи полей, рядом пишется `.review.json`. `publication_allowed` всегда
   false: правовая приёмка и публикация в этот этап не входят.
8. Сверка привязана контрольными суммами к сценарию и снимку темы. Сохранение
   без успешной сверки или с изменёнными данными запрещено и в библиотечном
   интерфейсе. Генерация и сверка не отмечают тему использованной.
9. Словарь категоричных фраз и распознавание реквизитов не покрывают все формы.
   Оговорка учитывается в том же предложении; её содержательную достаточность
   и соответствие источнику проверяет LLM, затем редактор. Отдельный дисклеймер
   не оправдывает обещание результата.

## 2026-10-23 — озвучка и тайминги

1. Пользователь выбрал ElevenLabs и тайминги сервиса. Реализован общий
   `TTSProvider` с методом `synthesize(text)`, без файлового ввода-вывода.
   Реализация возвращает WAV, метаданные и необязательные тайминги слов.
   Сохранение и резервная оценка находятся в отдельном пайплайне. Для будущего
   OpenAI достаточно отдельного адаптера и регистрации в фабрике, ядро не меняется.
2. Ключ и `voice_id` задаются как `ELEVENLABS_API_KEY`, `ELEVENLABS_VOICE_ID`
   в `.env` для Docker Compose. Существующее правило сохранено: локальный Python
   сам `.env` не читает, использует переменные окружения. Ключи не выводятся
   в repr, логи и сохранённые метаданные. Пустые значения не мешают другим командам,
   но явно отклоняются при создании TTS-провайдера.
3. Выбран endpoint ElevenLabs `with-timestamps`, модель по умолчанию —
   `eleven_multilingual_v2`, настраиваемая через `ELEVENLABS_MODEL_ID`.
   Запрашивается PCM 24 кГц, mono, signed 16-bit LE; WAV собирается стандартной
   библиотекой. MP3-декодер, FFmpeg и новые зависимости не требуются.
4. Посимвольные метки группируются по непустым словам с сохранением пунктуации.
   Приоритет у `alignment`, затем у `normalized_alignment`, если слова совпадают
   с исходным текстом с учётом Unicode NFC и различий пробелов. Например, замена
   чисел словами в нормализованной версии не считается точной привязкой к исходнику.
   Проверяются полнота, конечность, порядок и границы. Допускается обрезать только
   до 20 мс округления за фактическим концом WAV; метки дальше отклоняются.
5. Если таймингов нет или корректные массивы относятся к другому тексту,
   используется `phrase_length_v1`: фактическая длительность WAV делится по
   длинам фраз и слов. Вес слова — число букв и цифр (минимум 1); вес паузы после
   `. ! ? …` — 6, после `, ; :` — 3, перед новым абзацем — минимум 9.
   Все веса масштабируются на длительность аудио. Финальная пунктуация может
   оставить оценочную паузу в конце. Это **допущение, а не распознавание речи**:
   метаданные явно содержат `timing_source: estimated`, метод и причину.
   Темп, ударения и реальные паузы этим способом точно не определяются.
6. Повреждённые массивы, отрицательные/NaN-метки, несовпадающие длины массивов,
   пересечения слов и повреждённое аудио вызывают ошибку, без тихой замены
   приблизительными метками. Успешный HTTP 200 с некорректным ответом повторно
   не генерируется, чтобы не создавать дополнительные оплачиваемые дубли.
   Только временные HTTP/транспортные ошибки повторяются ограниченно через `TTS_*`.
7. Команда `tts` принимает сценарий с успешной сверкой и проверяет её контрольные
   суммы, доказательства и текущие локальные правила до вызова провайдера.
   Озвучивается ровно `voiceover`, включая хук и CTA, без их повторного добавления.
   Дисклеймер остаётся отдельным полем для будущего оформления видео.
8. На выходе новая папка с `audio.wav` и `timings.json`, появляющимися вместе
   после успешной записи. Аудио и исходный текст привязаны контрольными суммами.
   История использования и разрешение публикации не меняются. Длительность
   сообщается фактическая: речь не обрезается и не ускоряется ради 30–60 секунд.


## 2026-10-24 — рендер вертикального видео

1. Используется прямой FFmpeg без MoviePy: существующих Python-зависимостей
   достаточно. FFmpeg/ffprobe и DejaVu Sans с кириллицей установлены в Docker.
   Формат фиксирован: 1080×1920, 30 fps, H.264/yuv420p, AAC, MP4/faststart.
2. Пользователь попросил оставить название и контакты услуги настраиваемыми.
   В YAML-шаблоне `service_name` и `contact` пусты. Незаполненные поля не
   показываются; финал содержит согласованный SCRIPT_CTA и дисклеймер.
   Длительность финала по умолчанию — 3 секунды, изменяется от 1 до 10.
3. Максимум 90 секунд относится ко всему ролику вместе с финалом. При
   превышении — ошибка с предложением перегенерировать речь; голос не ускоряем
   и не обрезаем. Добавленная пауза округляется вниз на сетку 30 fps (до 1/30 с).
4. Синхронные титры — весь voiceover по сохранённым меткам слов, группами
   до 5 слов/42 символов с явным переносом примерно по 21 символу. Отдельные
   on_screen_text не дублируются, так как для них нет привязки к словам.
   Оценочные метки сохраняют timing_source: estimated, без заявления точности.
5. Плашки норм берутся только из проверенных sources: law, article, part, URL.
   Несколько карточек сменяются равными интервалами речи. Полные URL переносятся,
   выдуманные короткие ссылки не создаются. Дисклеймер виден постоянно.
6. Без --clips-dir фон — градиент. Локальные клипы идут по имени, нормализуются
   до общего размера/частоты кадров, заполняют экран обрезкой по центру,
   повторяются до конца; их звук не используется. Максимум 20 клипов за запуск,
   длинный клип используется максимум на длительность ролика. Скачивания нет.
7. До сборки повторно проверяются сохранённая сверка сценария и привязка TTS
   по контрольным суммам, WAV-длительность и все тайминги. После сборки ffprobe
   проверяет формат, кодеки, размер и длительность обоих потоков. Результат —
   отдельная атомарно сохраняемая папка с видео, ASS и журналом метаданных.
   История тем, внешние сервисы и разрешение публикации не изменяются.
8. Тестовые ролики используют синтетическую тишину и учебные реквизиты,
   явно обозначенные как нереальные в фикстурах. Они проверяют монтаж и формат,
   реальная интонация и точность ElevenLabs требуют настоящего аудио.


## 2026-10-24 — Instagram, S3, ручное одобрение и полный запуск

1. Пользователь выбрал Instagram Login по умолчанию; способ входа настраивается
   (`instagram`/`facebook`). API version пользователь задаёт явно по своему Meta
   приложению, чтобы код не угадывал актуальную версию. OAuth/UI получения токена
   в этот этап не входят, Business/Creator ID и токен хранятся в .env.
2. По запросу добавлен только S3 через VideoStorage/boto3, без локального
   HTTP-сервера. Endpoint, bucket, region и ключи задаются в .env. Публичный
   корень необязателен; иначе SigV4 presigned GET, TTL по умолчанию 7200 с.
   ACL не изменяются, SDK не использует неявные ключи AWS-профиля/instance metadata.
3. Загрузка — после одобрения и проверки квоты, перед созданием контейнера REELS.
   После успеха сначала сохраняется результат, затем удаляется объект; удаление
   отключается S3_DELETE_AFTER_PUBLISH=false. Неудачная очистка не отменяет успех
   и повторяется без повторной публикации. URL с подписью не сохраняется в state.
4. Согласован порядок: run-all -> просмотр -> approve ID -> publish ID.
   approve не публикует. Одобрение связывает все файлы, аккаунт и share_to_feed.
   История использования сохраняет отдельный mark-used, без автоматической отметки.
5. Черновик — самостоятельная папка с копиями всех полученных материалов.
   На ошибке остаются уже созданные сценарий/аудио/видео и причина по этапу.
   Аудит LLM не выдаёт разрешение публикации: ручное одобрение отдельно в state.
   Сервисные JSON обновляются атомарно; SQLite-блокировка сериализует публикации
   в общей папке и автоматически освобождается при аварии процесса.
6. run-all --dry-run по явному выбору пользователя не вызывает сеть, S3, LLM
   или TTS, не создаёт черновиков/папок и не изменяет историю. Проверяет форматы
   ключей, локальные инструменты/шрифт/шаблон, источники и права папок. Показывает
   модель, голос, число роликов и оценку запросов с верхней границей ретраев.
   Действительность ключей, квоты, доступность DNS и стоимость без сети неизвестны.
7. --stub или PIPELINE_MODE=stub использует учебный текст с явно вымышленными
   реквизитами, локальный 30-секундный тон и настоящий FFmpeg. Все такие комплекты
   имеют mode=stub и аудит local-stub; approve/publish и импорт как live блокируются.
   Оценочные метки тут нужны только для проверки оформления, речи в тоне нет.
8. Число роликов --count по умолчанию 1, допустимо 1–10. В каждом одна выбранная
   тема; подборка задаёт число отдельных сценариев. --count в collect не изменён.
   Заглушки не читают и не записывают историю, live сохраняет штатную историю сбора.
9. Токены передаются в Authorization, не в URL. Из API-ошибок сохраняются лишь
   контролируемые причины. HTTP/SDK debug-логи подавлены; фильтр удаляет настроенные
   секреты и URL с query из журналов. CLI теперь читает локальную .env через
   python-dotenv (ранее требовался экспорт окружения); окружение имеет приоритет.
10. Квота читается из Graph API, а не фиксируется как число постов. Ретраи временных
    ошибок экспоненциальные, Retry-After не сокращается. Длинная пауза записывается
    для следующего запуска. По умолчанию до 5 проверок обработки с паузой 60 с.
11. Потеря ответа media_publish и 5xx дают неопределённый результат. Автоматический
    второй POST запрещён: повторный запуск проверяет сохранённый контейнер.
    PUBLISHED подтверждает успех; если media_id потерян, сохраняется null.
    FINISHED при неопределённом исходе требует ручной проверки Instagram.
12. Итоговая подпись — проверенная caption + дисклеймер + хэштеги; новые правовые
    утверждения не добавляются. Общая подпись ограничена 2200 символами; собственная
    caption сценария по-прежнему ограничена 1000. Источники остаются в плашках и JSON.
    Для совместимости Reels рендер ограничен 25 Mbps видео и использует AAC 128 kbps.
13. MinIO — отдельная локальная проверка на loopback. Готовые релизные образы
    оказались недоступны; добавлена сборка из фиксированного исходного релиза
    2025-10-15 с исправлениями. Ключи локального теста пользователь задаёт отдельно.
    Публичное облако и реальные разрешения Meta мок-тестами не подтверждаются.

## Итоговый аудит пайплайна и документации

- Согласованный `run-all --dry-run` остаётся проверкой готовности и планом:
  он не запускает генерацию, TTS, рендер или публикацию. Сквозной проход с
  реальным MP4 отдельно проверяется режимом `--stub` и интеграционными тестами.
- Для воспроизводимой проверки добавлены `tests/fixtures/preflight.env` и
  `preflight.yaml`: только синтетические ключи, примерные домены и версия API
  как образец формата. Их нельзя использовать как рабочую конфигурацию.
- Проверка dry-run выполняется также в отдельном интерпретаторе с настоящими
  медиатулзами, запретом сети и сравнением файлов до/после. Отдельный запуск
  аудита выполнен в Docker с `--network none`, read-only корнем и кодом.
- Конфигурация, в которой отключены все источники, считается ошибочной:
  иначе проверка готовности давала бы положительный результат без возможности
  собрать темы. Тест проверяет это до любого обращения к источникам.
- Покрытие измеряется coverage.py для всех модулей `app`, включая ветви;
  минимальный совокупный показатель — 90%. Инструменты coverage, Pyflakes и
  Vulture закреплены только в dev-зависимостях. Автоматический запуск GitHub
  Actions не включается: прежнее решение о паузе сохранено.
- Удаляются подтверждённые неиспользуемые импорты. Модули старого локального
  текстового редактора остаются: команда `--draft` и её проверки используются.
  Поля dataclass, сериализуемые через `asdict`, и поля стандартного LogRecord
  не удаляются по эвристическим предупреждениям Vulture.

## Ролики для привлечения клиентов — этап 2, 1 ноября 2026

## 2026-11-02 — корректировки после просмотра engaging-reels-demo

- Фотографии не затемняются по всему кадру: brightness=0, без виньетки,
  затемняющих плашек на половину кадра и переходов через чёрный. Читаемость
  текста обеспечивают локальные непрозрачные подложки. Запасной градиент светлый.
- Частицы «ли, бы, же, то, не, ни» присоединяются к предыдущему слову и не
  начинают экран/строку. Внутри экрана частица может завершать строку вместе
  с предыдущим словом; предлоги и союзы от следующего слова не отделяются.
  Если вход начинается с одиночной частицы без предыдущего слова или не
  помещается в заданные 2–5 слов, рендер останавливается без потери слов.
- Под «висящей пунктуацией» понимаем запятую, двоеточие, точку с запятой и
  тире на границе экрана: убираем их только из отображения, сохраняя исходную
  речь и тайминги. Завершённые предложения сохраняют точку/вопрос/восклицание.
- CTA занимает последние 5–6 секунд (по умолчанию 5,5, cta_seconds в шаблоне)
  одновременно с озвучкой, без добавленного тихого хвоста. Полноэкранный
  светлый фон закрывает иллюстрации; обычные титры, нормы, числа, логотип и
  служебные блоки заканчиваются до него. Ключевое слово выделено отдельно;
  текст не уменьшается ниже 60 px. Дисклеймер остаётся в безопасной зоне в конце.
- Новая схема генерации требует editorial.scenes: упорядоченные дословные
  фрагменты речи и теги сцены. Старые проверенные сценарии без scenes читаются
  без изменения сериализации/контрольных сумм и получают запасной фон.
  library.yaml связывает локальные файлы и теги; выбираем по наибольшему
  пересечению тегов сцены с максимальным временным перекрытием кадра.
  При равенстве — реже использованный подходящий файл. Нет совпадения — фон,
  без выбора несвязанной картинки. asset=-1 в плане означает запасной градиент.
- Случайные круговые иллюстрации и неиспользуемый их генератор удалены.
  Три новые оригинальные фотографии созданы встроенным imagegen; промпты и
  происхождение описаны в assets/visuals/README.md. В репозитории JPEG-экспорт,
  исходные PNG сохранены рядом с демо за пределами репозитория.
- Тестовая плашка формируется по явному режиму stub в самом рендерере, а не
  путём записи временного тестового шаблона. run-all передаёт режим; отдельная
  команда render поддерживает --stub. В live предупреждение не появляется даже
  при случайно переиспользованном старом шаблоне с тестовым заголовком.
- Для короткой нормы распознаём также произнесённые числительные 1–20;
  реквизиты берутся только из уже проверенного источника, новые не создаются.
- Два демонстрационных результата разделены: stub с тоном и вымышленными
  реквизитами, и отдельный preview с сохранённой речью Eric из прошлого демо
  и новым CTA тем же голосом. Правовые утверждения preview не переписывались.
  Preview не получает фиктивной LLM-проверки или допуска к публикации:
  внешняя сверка и ручное юридическое одобрение остаются непройденными.
