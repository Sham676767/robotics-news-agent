## Что проверяют тесты

- Старые сценарии читаются; новая генерация требует editorial, 2–3 разных хука,
  выбранный вариант, формат, три коротких пункта, одно-два действия, озвученную норму.
- Все хуки входят в сверку; источники/реквизиты нельзя подменить. Ошибки JSON
  вызывают ограниченные ретраи; ошибки сверки не обходятся.
- CTA содержит ключевое слово и напоминание сохранить; выигрыши/гарантии запрещены.
- Группы титров 2–5 слов; предлоги/союзы не остаются в конце фразы/строки.
  Пунктуация сохраняет перечисления. Длинная группа может занимать три строки
  вместо разрыва мысли; шрифт остаётся ≥60 px и измеряется настоящим TTF.
- Тестовый PCM с длинными паузами: их удаление, точная карта времён,
  сохранение исходного WAV, хвост ≤0,5 с и внутренние паузы ≤0,3 с.
- Лицензия музыки: отказ при неподтверждённом коммерческом использовании,
  неизвестной лицензии, обходе пути, отсутствующем файле/атрибуции, сломанном YAML.
- Реальный MP4 через ffprobe: кодеки/размер/длительность. План ≤4 с;
  дополнительно сравниваются реальные изображения первых двух планов.
- Безопасные зоны: не только координаты JSON, но и пиксели отрисованных ASS
  на чёрном кадре в начале/конце; верх, низ и правая полоса остаются пустыми.
- CTA в последних 8 с, дисклеймер только в конце, отсутствие экранных URL,
  норма только у произнесённой статьи, крупные цифры не путают «часть» с «часами».
- Обложка передаётся через thumb_offset; дата публикации сохраняется устойчиво,
  повторный publish не дублирует пост. Новые артефакты связаны хешами пакета.
- stats: GET Insights с токеном в заголовке, независимые метрики, пустые/битые/
  отрицательные/булевы значения не превращаются в ноль. Учитываются аккаунт,
  опубликованный пакет, хук/формат, размер выборки, корректные знаменатели.
- Внешние API замоканы; общая фикстура запрещает сетевые соединения.

## Ограничения и ручная проверка

Это техническое демо с явно вымышленными реквизитами и локальным тоном,
не реальный юридический выпуск или оценка естественности голоса. Для него не
использовались OpenRouter/ElevenLabs/S3/Instagram и не выдавалась правовая проверка.
На реальной озвучке нужны просмотр синхронизации и контроль, что тихие согласные
не задеты порогом тишины; при необходимости измените монтаж/повторите озвучку.

Live dry-run текущего .env выявил недостающие OpenRouter, Instagram и S3 настройки.
Ключ ElevenLabs/выбранный голос не изменялись. Сервисные квоты, разрешения и реальная
статистика аккаунта без заполненных настроек не проверялись.

Сообщения: у Media Insights нет надёжной атрибуции входящих обращений к Reel.
messages=null объясняется в отчёте. Число сообщений аккаунта не выдаётся за заявки
конкретного ролика; для этого нужен отдельный учёт уникальных CTA-кодов/CRM.
Статистика с mock API проверена; реальный доступ Insights проверяет владелец аккаунта.

Перед первой публикацией:

1. Заполнить CTA-контакт, имя/логотип, проверить цвета и права на свои медиа/музыку.
2. Заполнить недостающие API/S3 настройки, дать токену Insights-разрешение,
   повторить live dry-run; ключи остаются только в .env.
3. На телефоне просмотреть видео, обложку и контактный лист с учётом интерфейса Reels.
4. На реальном выпуске сверить норму и применимость, цифры, речь, момент карточки нормы,
   CTA и подпись; только затем approve и отдельный publish.
5. После публикации проверить выбранную обложку, stats и одинаковые окна наблюдения
   для вариантов хука. Заявки учитывать отдельно, без обещаний коммерческого результата.
