# Озвучка через TTSProvider

Первая реализация — ElevenLabs, выбранная пользователем. Пайплайн работает
с общим интерфейсом `TTSProvider.synthesize(text) -> SynthesizedSpeech`.
Адаптер возвращает 16-bit PCM WAV, данные о провайдере/модели/голосе и
необязательные `WordTiming(word, start, end)`. Он не сохраняет файлы.
Добавление другой реализации требует адаптера и регистрации в `tts_factory.py`;
общий пайплайн сохранения и синхронизации не меняется.

## Настройка и запуск

В `.env` заполните своими значениями:

```dotenv
TTS_PROVIDER=elevenlabs
TTS_OUTPUT_DIR=audio
ELEVENLABS_API_KEY=
ELEVENLABS_VOICE_ID=
ELEVENLABS_MODEL_ID=eleven_multilingual_v2
TTS_TIMEOUT=120
TTS_MAX_ATTEMPTS=3
TTS_RETRY_BASE_SECONDS=2
TTS_RETRY_MAX_SECONDS=20
```

Секрет и голос не зашиваются в код. `.env` исключён из Git, образ содержит
только `.env.example`. Docker Compose читает `.env` через `env_file`.
Для локального запуска Python читает `.env` из текущей папки проекта;
переменные окружения оболочки или IDE имеют приоритет.

```bash
docker compose build
docker compose run --rm agent python -m app tts --input drafts/reel-script-ID.json
# Локально, после настройки окружения:
python -m app tts --input drafts/reel-script-ID.json
python -m app tts --input drafts/reel-script-ID.json --output-dir audio/previews
```

Сценарий и соседний `reel-script-ID.review.json` должны быть результатами
успешного `script`. Проверяются контрольные суммы, все утверждения и цитаты,
статус и актуальные локальные запреты. При изменении текста или источников
нужен новый сценарий/сверка. Черновик из карантина не принимается.
Эта проверка не вызывает дополнительный запрос к LLM.

Озвучивается весь `voiceover` ровно один раз. Хук и CTA уже входят в него.
Подпись, хэштеги, титры, ссылки и отдельный дисклеймер не читаются автоматически.
TTS создаёт предпросмотр, не разрешение публикации; история тем не изменяется.

## Аудио и тайминги

Реализация вызывает [ElevenLabs Create speech with timing](https://elevenlabs.io/docs/api-reference/text-to-speech/convert-with-timestamps),
получает `audio_base64` и посимвольные метки. Выбран `pcm_24000`; PCM упаковывается
в WAV (24 кГц, mono, 16-bit) без внешних декодеров. Об использовании PCM см.
[официальные материалы ElevenLabs](https://github.com/elevenlabs/plugin/blob/main/skills/general/voice-changer/SKILL.md).

Результат: новая папка `TTS_OUTPUT_DIR/tts-<uuid>/` с двумя файлами:

- `audio.wav` — полученное аудио;
- `timings.json` — текст, метаданные, длительность, контрольные суммы и массив
  `word_timings`, у каждого слова `word`, `start`, `end` в секундах от начала аудио.

Длительность измеряется по числу кадров и частоте самого WAV. В стандартный
вывод CLI попадает JSON с путями, длительностью, числом слов, провайдером и
источником таймингов. Папка `audio/` исключена из Git и образа, в Compose она
подключена как `./audio:/app/audio`. Каждый запуск создаёт новый комплект.
Ошибки записи не оставляют половину нового комплекта.

`timings.json` также содержит `provider`, `model`, `voice_id`, `audio_sha256`,
`text_sha256`, `script_sha256`, `timing_source`, `timing_method`, `timing_note`.
Ключа API и тел ошибок сервиса в нём нет. `publication_allowed: false` и
`human_review_required: true` сохраняют необходимость последующей приёмки.

## Точные и оценочные метки

Обычный путь — `timing_source: provider`. У слова берётся начало первого и конец
последнего символа из меток сервиса. Пробелы разделяют слова, пунктуация рядом
со словом сохраняется. Проверяются совпадение исходных слов, порядок, конечность
чисел, отсутствие пересечений и выходов за длительность аудио.

Сначала используется `alignment`, затем `normalized_alignment`, если слова
совпадают с исходником. Допустима нормализация Unicode и пробелов. Если сервис
раскрыл число словами, такие метки не выдаются за точные для исходных цифр.
Расхождение за концом аудио до 20 мс допускается как округление и обрезается
по длительности WAV; большее расхождение — ошибка.

Если меток нет или корректная привязка относится к другому тексту, включается
`timing_source: estimated`, `timing_method: phrase_length_v1` с явной причиной.
Фразы и слова получают долю фактической длительности по числу букв/цифр;
пунктуация и абзацы добавляют веса пауз. Это техническая оценка, не распознавание
речи и не точная синхронизация. Формула и допущение записаны в `docs/decisions.md`.
Невалидные массивы, NaN, отрицательные времена и повреждённое аудио отклоняются
вместо скрытой замены оценкой.

## Ошибки и ручная проверка

Код завершения 0 — аудио и тайминги сохранены; 2 — ошибка, stdout пуст.
Недостающий ключ/голос, неизвестный провайдер и неверный сценарий отклоняются
до запроса. Временные HTTP/транспортные сбои повторяются до `TTS_MAX_ATTEMPTS`,
с ограниченной задержкой и `Retry-After`. Постоянные ошибки, включая 401/403/422,
и повреждённый успешный ответ не повторяются. При сетевой потере ответа
повтор может создать дополнительную генерацию у сервиса; при необходимости
можно задать `TTS_MAX_ATTEMPTS=1`.

После настройки настоящего ключа и голоса нужно прослушать результат, проверить
произношение реквизитов/сокращений, темп и совпадение слов с аудио. Оценочные метки
требуют особенно внимательного просмотра с титрами. Контролируйте фактические
30–60 секунд и хук около трёх секунд: модуль не обрезает и не ускоряет речь.
Видео, рендер титров, публикация и вторая реализация TTS в этот этап не входят.
