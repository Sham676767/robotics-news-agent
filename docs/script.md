# Генерация сценария

Команда `python -m app script` читает сохранённую подборку `collect` и вызывает
OpenRouter с моделью из `OPENROUTER_MODEL`. Реальные запросы требуют ключа
`OPENROUTER_API_KEY` в окружении; Python сам `.env` не загружает.
Docker Compose передаёт `.env` через `env_file`.

```bash
python -m app collect
python -m app script
python -m app script --input data/another-collection.json --topic-id topic-ID --output drafts/new-script.json
```

Вход по умолчанию: `data/collected_topics.json`. Подборка должна иметь статус
`ok` или `partial`, непустые `selected_topics`, материалы и первоисточники с
`availability_verified: true`. При нескольких темах обязателен `--topic-id`:
один вызов создаёт сценарий ровно одной темы. Некорректный вход отклоняется
до сетевого запроса. Пути `--input` и `--output` независимы от `sources.yaml`;
для нестандартного пути подборки его нужно явно передать в `script`.

## Контракт

У JSON ровно семь полей, дополнительных ключей нет:

| Поле | Значение и проверка |
| --- | --- |
| `hook` | Непустая русская фраза одной строкой, 1–8 слов |
| `voiceover` | Вся озвучка, 80–140 слов, четыре непустых абзаца |
| `on_screen_text` | Непустой массив непустых русских строк |
| `caption` | Непустая русская подпись |
| `hashtags` | Непустой массив уникальных `#слов`, буквы RU/EN, цифры, `_` |
| `sources` | Все исходные карточки `title`, `url`, `citation` без изменений; порядок свободный |
| `disclaimer` | «Информация носит общий характер и не заменяет индивидуальную юридическую консультацию.» |

Четыре абзаца `voiceover` разделяются пустой строкой и означают: хук → суть →
действия зрителя → CTA. Первый абзац дословно равен `hook`, последний —
`SCRIPT_CTA` (допускается финальная точка, вопросительный или восклицательный
знак). По умолчанию CTA: **«Сохраните ролик и поделитесь им»**.
И CTA, и хук входят в подсчёт 80–140 слов. Последовательности букв/цифр
считаются словами; слово через дефис считается одним. Подпись, титры, ссылки
и disclaimer в число слов озвучки не входят.

Лимит восьми слов — техническое приближение хука на три секунды. Ни длительность
хука, ни 30–60 секунд всего ролика не измеряются без озвучки. Структура
абзацев проверяется формально; смысл и полезность каждого блока проверяет редактор.

## Источники и достоверность

Карточки источников формируются программой до запроса. Для первоисточника
`title` и `citation` равны извлечённым реквизитам: сборщик пока не хранит отдельный
заголовок документа. Для новостной публикации `title` — её заголовок, `citation`
пустой, чтобы не приписывать ей чужие реквизиты. Все URL копируются из подборки.
Модель обязана вернуть эти карточки: лишняя, пропавшая или изменённая карточка
означает ошибку ответа и повторный запрос.

Промпт ограничивает модель материалами выбранной темы, задаёт аудиторию
предпринимателей и потенциальных клиентов юриста и запрещает выдумывать нормы,
сроки, суммы, реквизиты и выводы суда. Тексты источников передаются как данные,
а не как инструкции. Локально проверяются русский язык, некоторые рекламные
усиления, новые числа и распознаваемые правовые реквизиты, отсутствующие в
материалах темы. URL и имена издателей не служат доказательством числовых фактов.

Эти проверки ограничены: они не доказывают, что число использовано в верном
контексте, что все правовые ссылки распознаны, что вывод следует из нормы или
что её редакция актуальна. Доступность первоисточника берётся из снимка `collect`,
а не проверяется заново. **Каждый сценарий — черновик для правовой редакторской
проверки.** Сохранение не разрешает автоматическую публикацию.

## Ошибки, повторы и файлы

Используется `response_format: json_schema`, `strict: true`, затем независимая
локальная проверка всех полей и содержания. Поддержка схем зависит от выбранной
модели и провайдера — см. [документацию OpenRouter](https://openrouter.ai/docs/guides/features/structured-outputs).
Неподдерживаемая схема или модель могут вызвать HTTP-ошибку; код не переключается
на другой формат скрытно. Существующие запасные модели из конфига сохраняются.

Принимается только целый JSON-объект: Markdown, пояснения вокруг JSON, повторные
ключи и нечисловые константы NaN/Infinity отклоняются. Схема, число слов, структура
и источники проверяются внутри того же цикла повторов, что сетевые ошибки.
Всего не более `OPENROUTER_MAX_ATTEMPTS` HTTP-запросов (по умолчанию 3).
Невалидный ответ вызывает безопасную просьбу исправить формат. Исходный ответ,
текст исключения провайдера и ключ не записываются в логи. Постоянные HTTP-ошибки,
например 401, не повторяются. Временные ошибки и задержки обрабатывает общий клиент.

Код завершения: 0 — JSON проверен и сохранён; 2 — ошибка. При ошибке stdout пуст,
новый сценарий не создаётся. Существующий `--output` отклоняется до запроса.
После успешной проверки файл записывается атомарно без замены существующего
файла. Без `--output` каждый запуск создаёт отдельный файл с UUID в `DRAFTS_DIR`.
stdout и файл содержат один и тот же объект с семью полями; путь сохранения
пишется в stderr. Каталоги `drafts/` и `data/` исключены из Git.

Генерация сценария не изменяет историю использования. Подтверждение остаётся
отдельным действием: `python -m app mark-used topic-ID` после фактического использования.

## Что проверить вручную

1. С настроенным ключом запустить `collect`, затем `script` с выбранной моделью.
2. Сверить нормы, реквизиты, выводы и актуальность с полным первоисточником.
3. Прочитать `voiceover` вслух: хук около 3 секунд, полная речь 30–60 секунд.
4. Оценить понятность, пользу для целевой аудитории, титры, подпись и CTA.

Озвучка, монтаж, видео и публикация в этот этап не входят.
