# Сценарий и проверка по первоисточникам

Команда `script` выполняет генерацию, локальные проверки и отдельную LLM-сверку.
В обоих запросах используется модель из `OPENROUTER_MODEL` и настроенные запасные
модели. Нужен `OPENROUTER_API_KEY`. CLI читает локальный `.env`; переменные окружения имеют приоритет.
Docker Compose также передаёт его через `env_file`.

```bash
python -m app collect
python -m app script
python -m app script --input data/another-collection.json --topic-id topic-ID --output drafts/new-script.json
# Через контейнер с настроенным .env:
docker compose run --rm agent python -m app script
```

Вход по умолчанию — `data/collected_topics.json` со статусом `ok` или `partial`.
Если тем несколько, обязателен `--topic-id`: один вызов — один сценарий.
Нестандартный путь подборки передаётся в `--input` независимо от `sources.yaml`.
Генерация и сверка не меняют историю использования: `mark-used` остаётся отдельным действием.

## Контракт и лимиты

Новая генерация возвращает восемь полей. Старые семипольные файлы читаются
для совместимости, но новые ответы без `editorial` отклоняются:

| Поле | Требование |
| --- | --- |
| `hook` | Непустая русская фраза одной строкой, 1–8 слов |
| `voiceover` | Вся озвучка, 80–140 слов, четыре абзаца: хук → суть → действия → CTA |
| `on_screen_text` | 1–6 русских строк, до 60 символов каждая, без переносов внутри строки |
| `caption` | Хук, 2–3 строки пользы и точный CTA; до 1000 символов |
| `hashtags` | 3–5 уникальных `#слов`, буквы RU/EN, цифры, `_` |
| `sources` | Все карточки `title`, `url`, `citation`, `law`, `article`, `part` без подмены |
| `disclaimer` | Точная строка «Не является юридической консультацией» |
| `editorial` | `format`, `hook_variants` (2–3), `selected_hook` (индекс с нуля) |

Абзацы озвучки разделяются пустой строкой. Первый дословно равен `hook`, последний —
собранному из `CTA_TEXT`, `CTA_KEYWORD`, `CTA_CONTACT` призыву (финальные знаки
`. ! ? …` допустимы). Шаблон CTA поддерживает `{keyword}` и `{contact}`,
обязан содержать ключевое слово и напоминание сохранить; максимум 20 слов.
Обещания выигрыша, возврата денег и гарантированного результата в CTA запрещены,
включая условные. `SCRIPT_CTA` остаётся только для старого формата.

Первые 0–3 секунды: конкретная боль/деньги без «сегодня поговорим».
Суть — три предложения до 25 слов каждое; затем одно-два действия до 30 слов
каждое; в конце короткий CTA. Цель озвучки 80–95 слов, защитный диапазон 80–140.
Точный хронометраж известен после TTS; рендер требует 30–45 секунд.
Конкретная статья и закон должны прозвучать, все числа/сроки берутся из источника.

Форматы: `question_answer`, `three_mistakes`, `before_after`, `checklist`.
Для «было/стало» нужны обе редакции в источниках. Модель получает это требование,
его смысловую корректность проверяют LLM и редактор. Все варианты хука, включая
невыбранные, входят в сверку фактов. `hook` дословно равен выбранному варианту.
`HOOK_VARIANT=0/1/2` либо `script --hook-variant 1` фиксирует выбор; для повторного
эксперимента сохраняйте одинаковые остальные условия. Изменять готовый JSON без
повторной проверки нельзя: его хеш связан с источниками и результатом сверки.

Упаковка добавляет к проверенным строкам подписи исходные URL, дисклеймер,
лицензионную атрибуцию музыки при необходимости и 3–5 хэштегов. Готовая подпись
до 2200 символов; URL не показываются в самом видео.

## Конкретные нормы

Карточки формируются программой из источников до запроса. У первоисточника
`title` и `citation` содержат извлечённые реквизиты. `law` — обозначение закона
или кодекса, `article` — номер статьи, `part` — номер части. Часть может быть
пустой только для статьи без частей; это дополнительно проверяет LLM. У новости
`title` — заголовок, а реквизиты могут быть пустыми: первоисточник указан отдельно.

Нужна хотя бы одна конкретная норма с законом, статьёй и URL первоисточника.
Извлекаются явные связки вида «ч. … ст. … …-ФЗ» или «статья … … РФ».
Из отдельных чисел или несвязанных заголовков привязка не достраивается.
Нераспознанные формы блокируют результат до уточнения источника. Несколько норм
в документе дают отдельные карточки с тем же URL. Модель не заполняет пробелы
своими реквизитами. Наличие числа в сумме или дате не подтверждает номер статьи
или дела. Проверяются также связки закона, статьи и части целиком.

Сборщик сохраняет текст официального HTML в `primary_references[].content`.
Старые подборки читаются, но без текста не проходят новую проверку — нужен
повторный `collect`. Доступность PDF не объявляется извлечением его текста:
до отдельного этапа извлечения такие материалы остаются заблокированными черновиками.

## Категоричные формулировки

Обещания вроде «вам точно положено», «гарантированно получите», «никаких рисков»
без оговорки в том же предложении блокируются. Отдельный дисклеймер или условие
в соседнем предложении не снимают запрет. Содержательную достаточность оговорки
и её подтверждение источником проверяет LLM, затем редактор. Словарь и распознавание
реквизитов ограничены: они не покрывают все варианты естественного языка.

## Отдельная сверка LLM

Второй запрос — новая беседа с моделью, которая не продолжает диалог генератора.
Она получает сценарий, заранее перечисленные фрагменты и сохранённые тексты
первоисточников. Сверяются хук, вся озвучка (включая CTA), титры, подпись,
хэштеги и реквизиты. Одинаковый фрагмент проверяется один раз.

На каждый id нужен вердикт и причина: `supported`, `contradicted`, `insufficient`
или `non_factual`. Для `supported` обязательны URL и дословная цитата от 12 до
600 символов из официального текста. При сравнении цитаты нормализуются пробелы.
Для карточки нормы требуется именно её URL. Новости не заменяют первоисточники.
Пропущенные/повторные id, чужие URL и выдуманные цитаты отклоняются. Нормы и
категоричные обещания нельзя пропустить как непроверяемые рекомендации.

Валидные `contradicted` и `insufficient` блокируют сценарий сразу: модель не
переспрашивается ради получения одобрения. Невалидный формат или сетевой сбой
повторяются ограниченно. Сбой сверки означает блокировку. Локальные запреты
сохраняются даже при одобрении модели. Наличие цитаты подтверждает её происхождение,
но не доказывает правильность вывода или актуальность права. Нужна ручная редактура.

## Результаты и ошибки

Используются строгий JSON и JSON-схемы, затем локальная валидация. Markdown,
текст вокруг JSON, повторные ключи, NaN/Infinity не принимаются. Синтаксис,
структура, длина и подмена карточек проверяются во время генерации: при
исчерпании попыток новый сценарий не создаётся. Обе стадии используют общий
клиент OpenRouter и отдельные лимиты `OPENROUTER_MAX_ATTEMPTS`: по умолчанию
до 3 запросов генерации и 3 запросов сверки. Тела ошибок и ключи не логируются.

| Код выхода | Результат |
| --- | --- |
| 0 | Сценарий прошёл обе проверки, сохранён и выведен в stdout |
| 2 | Ошибка входа, генерации или записи; stdout пуст |
| 3 | Сценарий получен, но заблокирован проверками; сохранён в карантин, stdout пуст |

При успехе stdout и новый `DRAFTS_DIR/reel-script-<uuid>.json` (или `--output`)
содержат одинаковый JSON с полем editorial. Рядом записывается `имя.review.json`:
проверенные фрагменты с их текстом, полем, цитатами и причинами, снимок темы и
контрольные суммы. Сверка привязана к конкретному тексту и источникам; изменение
данных требует новой проверки. Библиотечное сохранение тоже требует успешной сверки.
Файлы не заменяются. Если запись сценария не удалась, новый аудит удаляется.

При блокировке нормальный `--output` не создаётся. Отдельный пакет
`DRAFTS_DIR/quarantine/reel-script-<uuid>.json` содержит `script`, `review` и `topic`.
В `review.issues[]` — код и причина, например `missing_norm`, `missing_primary_text`,
`invented_identifier`, `unsupported_norm`, `categorical_claim`, `unsupported_text`,
`missing_disclaimer`, `llm_contradicted`, `llm_insufficient`, `review_unavailable`.
Статус — `quarantined`, `eligible_for_next_stage: false`.

У успешного результата статус `checked`, но `human_review_required: true` и
`publication_allowed: false`. Этот этап не реализует правовую приёмку и публикацию.
Каталоги `drafts/` и `data/` исключены из Git. Путь результата пишется в stderr.
Существующие `--output` и соответствующий `.review.json` отклоняются до запросов.

## Что проверить вручную

1. С ключом выполнить `collect`, затем `script` с выбранной моделью.
2. Проверить `.review.json`: подтверждают ли цитаты выводы, не потеряны ли условия
   и исключения, верны ли номера, части и актуальная редакция первоисточника.
3. Оценить понятность и пользу для предпринимателей и потенциальных клиентов юриста.
4. Прочитать озвучку вслух и измерить хук около 3 секунд, весь ролик 30–60 секунд.

Озвучка, монтаж и публикация в этот этап не входят.
